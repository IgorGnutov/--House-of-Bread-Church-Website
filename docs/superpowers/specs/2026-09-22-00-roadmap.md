# Дорожня карта: CMS, Astro і SEO для сайту «Дім Хліба»

**Дата:** 2026-09-22
**Статус:** узгоджено, готово до планування реалізації

## Навіщо це

Сайту потрібна адмінка, щоб нетехнічна людина могла редагувати всі тексти й контент,
і повноцінне SEO. Поточний стан робить обидві задачі неможливими без перебудови:

- контент розподілений між `*-data.js`, розміткою `index.html` і повністю статичними
  `pastors.dc.html` / `leaders.dc.html`;
- `<title>` немає **на жодній** з 10 сторінок, як і `description`, OG, canonical,
  JSON-LD, `sitemap.xml`, `robots.txt`;
- англійська версія існує лише як перемикання `innerHTML` на тій самій адресі, тобто
  для пошуку її **не існує**;
- `support.js` — згенерований рантайм на 1717 рядків, вихідників якого немає в репозиторії.

## Зафіксовані рішення

| Питання | Рішення |
|---|---|
| Стек | Astro, статична збірка |
| CMS | Storyblok, безкоштовний тариф |
| Редакторів | 1 |
| Мови | uk (корінь) + en (`/en/`), обидві в пошуку |
| Слаги | англійські, спільні для обох локалей |
| Продакшн-хостинг | ukraine.com.ua, тариф «Швидкий» (SSH + SSL + Apache/OpenLiteSpeed) |
| Прев'ю-стенд | GitHub Pages, безкоштовно — віддається з підшляху `/--House-of-Bread-Church-Website/`, тому `BASE_PATH` у збірці є змінною |
| Збірка | GitHub Actions → `rsync` по SSH |
| Публікація | одразу в ефір, без кроку підтвердження |
| Дизайн | переноситься 1:1, змін немає |
| Нові сторінки | `/about/`, `/contacts/`, `/donate/` — посилання **лише у футері** |
| Канонічний хост | без `www`, редірект з `www` |
| Третя мова | не планується — ліміт Storyblok у 2 локалі не тисне |

### Чому не кастомна адмінка

Обраний обсяг (колекції + тексти головної + медіатека + дві мови) — це повноцінна CMS.
Кастом означав би самостійно реалізувати авторизацію, завантаження й стиснення зображень,
парні uk/en поля, валідацію, прев'ю та ревізії. Найгірший ROI з розглянутих варіантів.

### Чому не Payload

Payload потребує постійно працюючого Node-сервера й бази даних. Заявлений хостинг —
shared-тариф без Node. Крім того, це щомісячний рахунок і обовʼязок роками оновлювати
застосунок, чого проєкт не витягне організаційно.

## Залежності між специфікаціями

- **SEO → Astro.** Структура URL і схема локалей визначені у Спеці 2, але є вхідними
  даними для Спеки 1. Їх не можна міняти після того, як сторінки побудовані, і тим паче
  після індексації. Зафіксувати до старту.
- **Astro → Storyblok.** Схема даних визначена у Спеці 1 (як Astro Content Collections).
  Спека 3 лише відображає її на компоненти Storyblok. Схема описується один раз.
- **Astro → SEO.** Мета-теги, `hreflang` і JSON-LD проставляються спільним layout,
  тому реалізуються після того, як layout існує.

## Точка можливого запуску

Після Спеки 2 сайт повністю робочий: обидві мови за реальними адресами, повне технічне
SEO, той самий вигляд. Бракує лише можливості редагувати контент без коду. Якщо потрібно
запуститися раніше — це природна точка зупинки.

## Що не входить в розробку

Актуалізація контенту виконується після Спеки 3 силами замовника:

- реальні тексти замість поточних;
- реальні фото замість 31 заглушки `picsum.photos`;
- `title`, `description`, `alt` двома мовами;
- розгорнуті тексти для `/about/`, `/contacts/`, `/donate/` — без них ці сторінки
  не ранжуватимуться;
- підключення Search Console й перевірка індексації обох мов.
