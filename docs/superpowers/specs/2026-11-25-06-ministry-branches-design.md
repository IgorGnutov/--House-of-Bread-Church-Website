# Спека 6. Гілки служіння (розділ із підгрупами на сторінці служіння)

**Дата:** 2026-11-25.
**Порядок:** після Спеки 4 (richtext і адреси кнопок). Інструкція редактора (Етап 6) має описати новий блок.

## Мета і навіщо

На сторінці «Домашні групи» (`/ministries/home-groups/`) треба показати різні гілки домашніх груп: у кожної
своє фото й відео, назва, опис, лідер, телефон і кнопка «Долучитися». Редактор у Storyblok сам додає, змінює,
переставляє й видаляє гілки.

Це **необовʼязковий додатковий компонент будь-якого служіння**, а не особливість домашніх груп: назву розділу
(«Гілки», «Групи», «Команди»…) редактор задає для кожного служіння окремо, українською й англійською.

## Цілі

- Необовʼязковий блок «Розділ із гілками» у служінні: назва розділу `{uk, en}` + список гілок.
- Гілка: слайдер фото/відео, назва, опис, лідер, телефон, адреса кнопки «Долучитися» (порожньо — дзвінок на
  телефон гілки).
- Коли в служінні є хоча б одна гілка, загальні **лідер, телефон і кнопка «Долучитися» служіння не
  показуються** (у кожної гілки свої). Загальний слайдер, назва, коротко й опис служіння лишаються.
- Блоку немає або гілок нуль — сторінка така, як зараз (піксель у піксель).

## Не робимо

- Адреси, район, час зустрічі гілки — замовник явно відмовився.
- Окремі сторінки / адреси для гілок, якорі на гілки, гілки в «Інших служіннях», картках списку чи на головній.
- JSON-LD для гілок.
- Нових кольорів чи шрифтів — лише наявні токени й розкладка сторінки служіння.

## Анти-цілі (провал, навіть якщо «працює»)

- Сторінки служінь без гілок змінилися візуально.
- Редактор змушений заповнювати поля, яких сайт не показує (лідер/телефон служіння при наявних гілках).
- Схема приймає набір, який ламає збірку або `npm test`.
- Стрілки клавіатури гортають кілька слайдерів одночасно.

## Підходи

| | Підхід | Плюси | Мінуси |
|---|---|---|---|
| **А (обрано)** | Необовʼязкова вкладена група в служінні: `branches: {title, items[]} \| null` | Редагується у формі служіння (перетягування, додавання); той самий механізм, що `projects.stats`, `homepage.news.items`; convert / import / verify / checkModel підхоплюють рекурсивно | Довга форма при 15+ гілках |
| Б | Окрема колекція «Гілки» з посиланням на slug служіння | Кожна гілка — окрема історія | Звʼязки між історіями, сироти при перейменуванні/видаленні служіння, назва розділу все одно в служінні; складніше редактору |
| В | Універсальний конструктор блоків сторінки служіння | Гнучкість | Надмірно для одного типу блоку |

## Дані (схема, `src/lib/schema.mjs`)

```
ministryBranch = {
  name: localized,                // назва гілки
  body: localizedRich,            // опис (той самий рівень, що body служіння)
  leader: z.string().min(1),      // як у служінні — рядок без перекладу
  phone,                          // той самий формат, що в служінні
  ctaUrl: linkUrl.nullable(),     // «Долучитися»; null — tel: телефону гілки
  media: gallery,                 // ≥ 1 фото або відео YouTube
}.strict()

ministryBranches = {
  title: localized,               // назва розділу, напр. «Гілки» / «Branches»
  items: z.array(ministryBranch), // порожній список допустимий
}.strict()

ministries += branches: ministryBranches.nullable().optional()
```

**Лідер і телефон служіння стають необовʼязковими лише коли гілки є:** `leader` і `phone` у служінні —
`nullable`, а рівень обʼєкта `ministries` перевіряє: якщо `branches?.items.length` = 0 (або `branches` = null),
то `leader` і `phone` обовʼязкові (повідомлення з точним шляхом `leader` / `phone`). Це правило цілісності,
а не лічильник: сторінка без гілок мусить мати контакт.

«Гілки є» скрізь означає `branches && branches.items.length > 0` — одна функція (напр. `hasBranches(m)` у
`src/lib/collections.mjs`), якою користуються і схема, і шаблон.

Помилка «потрібен leader/phone» зʼявиться лише після того, як решта полів служіння валідна (refine на рівні
обʼєкта) — тести схеми мають це враховувати. Оскільки refine прибирає `.extend()` / `.omit()`, внутрішній
`z.object` служіння треба експортувати окремо (його використовує `tests/cms-model.test.js`, рядки 19–63).
`checkModel` refine уже розгортає (`unwrap()` у `check.mjs`).

Наявний seed `src/content/ministries/*.json` не змінюється: поле `branches` — `.nullable().optional()`, а в
моделі `optional: true, nullable: true`; `canonical`/`fillNulls` у `convert.mjs` дають `null` для відсутнього
ключа (як `pages.body`).

## Модель Storyblok (`src/lib/storyblok/model.mjs`)

- Новий компонент `ministry_branches` («Розділ із гілками»): `title: loc('Назва розділу')`,
  `items: list('Гілки', ['ministry_branch'])`.
- Новий компонент `ministry_branch` («Гілка»): `name: loc('Назва')`, `body: rich('Опис')`,
  `leader: text('Лідер')`, `phone: text('Телефон')`,
  `ctaUrl: url('Посилання кнопки «Долучитися» (порожньо — дзвінок на телефон гілки)')`,
  `media: list('Фото й відео', ['gallery_image', 'gallery_video'], { required: true })`.
- У `ministry`: `branches: group('Розділ із гілками', 'ministry_branches', { optional: true, nullable: true, tab: 'branches' })`
  на новій вкладці «Гілки» — її треба додати в `TABS` (`src/lib/storyblok/components.mjs`), інакше поле не
  потрапить у жодну вкладку; `leader` і `phone` — `nullable`, з підказкою «Можна лишити порожнім, якщо є гілки».
- `checkModel()` має пройти.
- Richtext гілок (`walk.mjs` / `mapRichPairs` / `mapImages`) і картинки галерей гілок (`assetValue` /
  `assetPath` / `assetRefs` у `convert.mjs`) уже йдуть за моделлю рекурсивно у вкладені групи й списки —
  нового коду не треба, але round-trip-тест має це підтвердити.

## Сторінка (`src/pages/[...lang]/ministries/[slug].astro`)

```
[ Шапка служіння — як зараз ]
[ слайдер служіння | eyebrow, коротко, опис, (лідер, телефон, Долучитися — лише без гілок) ]

            <h2> Назва розділу з CMS </h2>
[ слайдер гілки 1 | <h3> назва гілки, опис, лідер, телефон, [Долучитися] ]
[ слайдер гілки 2 | … ]

[ Інші служіння — як зараз ]
```

- Гілки — окрема `<section>` після основної, лише коли гілки є. Кожна гілка повторює наявну розкладку
  `.layout` / `.info` / `.facts` / `.btn` (на ≤900px — одна колонка, як зараз). Порядок — як у списку CMS.
- Заголовок розділу `h2`, назва гілки `h3` (ієрархія: `h1` служіння → `h2` розділу → `h3` гілки).
- Кнопка гілки: `linkAttrs(base, lang, branch.ctaUrl ?? telHref(branch.phone))`, підпис `cta.join`.
- Слайдер гілки: `<Gallery media={branch.media} videoTitle={`${назва гілки} — ${a11y.video}`} />`.
- Стилі — у `src/styles/pages/ministry.css` (без `<style>` в `.astro`), лише наявні токени.
- `SubPage` / SEO не змінюються (обкладинка — як зараз, з `m.media`).

## Слайдер (`src/components/Gallery.astro`)

Зараз кожен екземпляр вішає `keydown` на `document`, тож кілька слайдерів гортались би разом. Нове правило
(рішення будівника-дизайнера, не замовника): стрілки гортають **слайдер, з яким людина взаємодіяла
останнім** (`pointerdown` або `focusin` усередині нього — клік по фото теж рахується, і Safari, що не фокусує
кнопку при кліку, теж). Поки взаємодії не було — **перший слайдер, який має більше одного слайда** (у
слайдера з одного слайда гортати нічого). Один спільний обробник `keydown` на сторінку, а не по одному на
слайдер. На сторінках з одним слайдером поведінка не змінюється.

## Тести (`npm test`)

Правила, не поточні дані; крайові випадки — пробними збірками з тимчасової копії контенту
(`tests/helpers/build.js`, `HOB_CONTENT_DIR`):

- схема: служіння з гілками без `leader`/`phone` — валідне; без гілок і без `leader` (або `phone`) — помилка
  з точним шляхом; гілка без `media`, з неправильним `phone`, `ctaUrl` = `#`, порожньою назвою мовою — помилка;
  `branches` з `items: []` валідне.
- збірка: служіння з 2 гілками → секція з назвою розділу (обидві мови), по одному `[data-gallery]` на гілку,
  `h3` з назвами, кнопка гілки веде на `ctaUrl` або `tel:` телефону гілки; загальні лідер/телефон/кнопка
  служіння відсутні. Служіння з `items: []` → секції немає, загальні контакти є.
- гілка з одним фото — без стрілок/мініатюр (як наявне правило Gallery).
- `site.test.js` (биті посилання, дублікати id) покриває нові сторінки автоматично.
- `cms-model` / convert: round-trip `toStory`→`fromStory` служіння з гілками дає той самий запис; історія без
  ключа `branches` дає `null`.
- e2e (Playwright, гілки вставляються в тимчасову копію контенту `scripts/e2e-build.mjs`): на сторінці з
  кількома слайдерами стрілка → гортається лише перший багатослайдовий; після кліку по фото другого — лише
  другий.
- **Наявні тести стануть гілко-залежними**, щойно редактор додасть гілки (CI ганяє `npm test` на контенті з
  Storyblok): `tests/page-ministries.test.js` (рядки 54–55: перший `.fact .val`, `.info .btn`) і
  `tests/e2e/gallery.e2e.js` (локатор `[data-slide].is-active` на всю сторінку) треба обмежити першим
  слайдером / основним блоком і зробити так, щоб вони очікували контакти служіння лише коли гілок немає.

## Після злиття (живий Storyblok)

`npm run cms:import` (dry-run: нові компоненти `ministry_branches`, `ministry_branch`, нові поля служіння) →
`-- --apply` → dry-run 0 змін → `cms:verify`. Потім редактор додає гілки «Домашнім групам» у Storyblok.
