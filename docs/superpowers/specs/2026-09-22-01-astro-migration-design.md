# Спека 1. Міграція на Astro

**Дата:** 2026-09-22
**Порядок:** реалізується **першою**. Вхідні дані — рішення про URL зі Спеки 2.

## Мета

Перевести сайт зі статичного HTML з рантаймом `support.js` на Astro зі статичною збіркою,
не змінивши зовнішній вигляд, і винести весь контент у типізовані дані.

## Не-мета

- Зміни дизайну, верстки чи структури сторінок — переносимо **1:1**.
- Підключення CMS — це Спека 3.
- Заміна заглушок `picsum.photos` на реальні фото — це актуалізація контенту.

## Поточний стан

| Факт | Значення |
|---|---|
| Сторінок | 10 (`index.html` + 9 `*.dc.html`) |
| `support.js` | 1717 рядків, згенерований, вихідників `dc-runtime` у репо немає |
| Дублювання `@font-face` | 8 блоків × 10 файлів = **80 копій** |
| Дублювання `:root` | 2 × 10 = **20 копій** |
| Ключів інтерфейсу `data-i18n` | **190 унікальних** (index 100, leaders 45, pastors 41, решта 6–11) |
| Файли даних | `ministries-data.js`, `churches-data.js`, `projects-data.js`, `testimonies-data.js` |
| Без джерела даних | `pastors.dc.html` (11 осіб), `leaders.dc.html` (6 документів + 6 ресурсів) |
| Збірка | відсутня |

CSS інлайниться в кожну сторінку, тому **не кешується між переходами** — браузер щоразу
качає ті самі кілобайти заново.

## Маршрутизація і локалі

Вбудований i18n-роутинг Astro: `defaultLocale: 'uk'`, `prefixDefaultLocale: false`.
З **одного** набору файлів генеруються обидві локалі — дублювати 20 файлів маршрутів
не потрібно. Повна карта URL — у Спеці 2.

## Модель контенту

Визначається тут, бо реалізується першою (як Content Collections зі схемою).
Спека 3 лише відображає її на компоненти Storyblok.

### Глобалі — по одному запису на сайт

| Запис | Поля |
|---|---|
| `site-settings` | назва (uk/en), логотип, домен, `defaultOgImage`, соцмережі (FB, YouTube, Instagram, Telegram) |
| `contact-info` | адреса (uk/en), місто (uk/en), `geo.lat`, `geo.lng`, телефон, email, день і час служіння (uk/en), посилання на карту |
| `donate-settings` | посилання LiqPay, суми-пресети для калькулятора в герої |

`contact-info` — **єдине джерело правди** для фактів. Їх читають і головна, і `/contacts/`,
і футер, і JSON-LD. Без цього адреса розійшлася б по кількох місцях і розсинхронізувалася.

`geo.lat` / `geo.lng` — нові поля, зараз їх немає ніде. Потрібні для розмітки `Church`.

### Сторінки-одиночки

| Запис | Вміст |
|---|---|
| `homepage` | 100 ключів `index.html` **без змін тексту**, згруповані по секціях: `hero`, `about`, `beliefs` (7), `news` (3 картки), `wwb` (4), заголовки секцій, футер |
| `page-about` | власні `title` + `body` (rich text), окремі від тексту головної |
| `page-contacts` | власна проза; факти тягне з `contact-info` |
| `page-donate` | власна проза; реквізити з `donate-settings` |
| `page-leaders` | заголовки `leaders.dc.html` |

Умова: `homepage` заходить у модель **без жодних правок тексту** — інакше головна
змінить вигляд, а ми домовилися переносити 1:1.

### Колекції

| Колекція | Джерело | Поля |
|---|---|---|
| `ministries` | `ministries-data.js` | `slug` (= поточний `id`), `icon` (**enum з 18 значень**), `leader`, `phone`, `name`/`summary`/`body` × uk/en, `media[]`, SEO |
| `churches` | `churches-data.js` | `slug`, `name`/`city`/`role`/`address`/`times`/`lead`/`body` × uk/en, `pastor`, `geo`, `media[]`, SEO |
| `projects` | `projects-data.js` | дзеркалить наявну структуру + SEO |
| `testimonies` | `testimonies-data.js` | `text`/`name`/`role` × uk/en, фото |
| `pastors` | **нова**, з `pastors.dc.html` | 11 осіб: `name`, `role` (uk/en), `bio` (uk/en), фото, `order`, `group` (пастори / пресвітери) |
| `leader-resources` | **нова**, з `leaders.dc.html` | 6 документів + 6 посилань: `title`/`description` (uk/en), файл або URL, `type` |

`media[]` — `{ type: "image" | "video", src, alt }`; `video` приймає URL або ID YouTube.
`alt` обовʼязкове — воно потрібне і для доступності, і для SEO.

`icon` — **строго список** із 18 значень (`index.html:775-793`). Іконки це inline SVG у коді;
довільне значення зламає картку мовчки, тому схема має його відкидати.

### Що свідомо не в даних

- **Меню й посилання футера** — у шаблоні. Навігація стабільна, а можливість зламати
  посилання на всіх сторінках не варта зручності.
- **Набір іконок** — фіксований список, не завантаження файлів.
- **Шрифти й токени дизайну** — у спільних CSS-файлах.
- **Тексти інтерфейсу** (кнопки, підписи) — `uk.json` / `en.json`, це не контент.

### Валідація

Схема колекцій перевіряється на збірці. Якщо у записі зникне `slug` або `icon` буде
не зі списку — **збірка падає з помилкою**, а не сторінка ламається в продакшені.

## CSS

- `fonts.css` + `tokens.css` + `base.css` підключаються з layout і кешуються один раз
  на весь сайт — замість 80 і 20 інлайн-копій;
- стилі конкретної сторінки лишаються в її `.astro` і ізолюються автоматично.

Побічний ефект: розмір HTML кожної сторінки помітно падає, зʼявляється реальне кешування CSS.

## Інтерактив: інвентар і доля

| Поведінка | Доля |
|---|---|
| Рендер сітки служінь із `window.HOB_MINISTRIES` | **зникає з клієнта** → робиться на білді |
| Пошук запису за `?id=` на деталках | **зникає** → `getStaticPaths()` |
| Перемикач мов (`applyLang`, `localStorage`) | **зникає** → звичайні посилання, деталі у Спеці 2 |
| Калькулятор пожертв у герої | переноситься як є |
| Липкий хедер при скролі | переноситься |
| Мобільна шторка | переноситься |
| Карусель свідчень | переноситься |
| Вставка YouTube по кліку у свідченнях | переноситься |
| Активний пункт меню (`IntersectionObserver`) | переноситься |
| Поява блоків при скролі, анімація героя | переноситься |
| «Повернення до секції, з якої пішов» | спрощується — з реальними URL логіка інша, перевірити що нічого не загублено |
| Галерея на деталках (стрілки, крапки, мініатюри, лінива вставка YouTube) | переноситься **в один компонент** замість трьох копій |

Astro не вимагає React чи Vue: звичайний `<script>` усередині компонента збирається як є.
Переписувати поведінку не потрібно.

## Рецепт перенесення однієї сторінки

1. `<style>` розрізається: шрифти й токени → спільні файли, решта → `<style>` компонента.
2. Розмітка переноситься в `.astro`; тексти замінюються на `t('key')` або поле з даних.
3. Тіло `componentDidMount` переїжджає в `<script>` компонента — мінус пошук даних
   і мінус перемикач мов.
4. На деталках `?id=` замінюється на `getStaticPaths()`.

## Витягування статичного контенту

`pastors.dc.html` і `leaders.dc.html` зараз не мають джерела даних — щоб додати пресвітера,
треба редагувати HTML. Витягнути:

- **11 осіб** з `pastors.dc.html` (3 пастори + 8 пресвітерів; імена в `<h3>` без ключів
  i18n, ролі й описи — з ключами);
- **6 документів + 6 ресурсів** з `leaders.dc.html` (ключі `doc1..doc6`, `res1..res6`).

## Деплой

```
GitHub Actions → astro build → rsync по SSH → ukraine.com.ua
```

- тариф «Швидкий»: Apache / OpenLiteSpeed, безкоштовний SSL, SSH, 10 ГБ, 1 сайт;
- Node на сервері **не потрібен** — Astro віддає звичайну статику;
- PHP і MySQL не використовуються взагалі, що прибирає цілий клас ризиків;
- SSH-ключ у секретах репозиторію; `rsync` заливає лише змінене;
- `.htaccess` (чисті URL, редіректи, кеш, стиснення) — описано у Спеці 2.

**Етап 0 робиться першим і наскрізно**: порожня сторінка має автоматично збиратися
й опинятися на хостингу під HTTPS. Деплой на shared-хостинг — єдина частина плану,
яку ще не бачили в роботі; дешевше перевірити її до основних вкладень.

## Етапи

| Етап | Зміст | Днів |
|---|---|---|
| 0 | Каркас Astro, спільний layout, наскрізний деплой | 0.5–1 |
| 1 | Контент у типізовані файли, 190 ключів, витягування пасторів і ресурсів | 1–1.5 |
| 2 | Перенесення 10 сторінок, галерея в один компонент, інтерактив | 5–8 |

## Перевірка

- Посторінкове порівняння зі знімками поточного сайту, **десктоп і мобільний** — головний
  контроль того, що дизайн не поїхав.
- Обидві локалі відкриваються за реальними адресами.
- Уся інтерактивність зі списку вище працює.
- Збірка падає, якщо навмисно зіпсувати запис у колекції.

## Ризики

| Ризик | Мітигація |
|---|---|
| Візуальні регресії при винесенні шрифтів і токенів у спільні файли | посторінкове порівняння зі знімками; це найімовірніше місце поломки |
